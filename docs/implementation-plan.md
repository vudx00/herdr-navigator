# Implementation plan

## Scope and decision order

This plan follows [Navigator experience](navigator-experience.md). Its machine search and native new-workspace requirements override the older machine-then-source layout and separate Agent destination proposals in [Multi-machine navigation](multi-machine-navigation.md). [Architecture](architecture.md) describes the current implementation, not the target interaction.

Build one picker. An empty query shows machines, workspaces, tabs, and panes. Typing shows flat fuzzy results. Clearing by editing restores browse state. Agents add metadata to exact pane destinations. Projects, folders, sessions, and commands retain their explicit actions and known owners.

A machine is an actionable result. Searching `void` must return `void.dev` itself under Type All or Machines. Enter opens Herdr's native new-workspace naming flow on that machine, with that machine's defaults. It does not merely switch machines or create an unnamed workspace. This also applies to Local and browse machine rows.

This document schedules work. No implementation, build, live discovery, focus, connection, or workspace creation was performed while preparing it. All new module names and client operation names below are proposals.

## Source baseline

The plan is based on these repository reads and the versioned upstream evidence recorded in Navigator experience.

| Current code | Change required |
| --- | --- |
| `src/sources.rs::collect_workspaces` calls workspace and pane lists, then discards panes except cwd. Unknown workspace cwd becomes process home. | Keep every pane and its ancestry. Treat missing cwd as unknown. Report provider failure separately from empty data. |
| `agents_from_json` produces Agent entries and uses terminal IDs as `FocusAgent` targets. | Join by qualified pane ID and dispatch exact pane focus, including when terminal and pane IDs differ. |
| `src/model.rs` combines source, display, path, and action in `Entry`. `Entry::key` canonicalizes paths. | Separate destination kind, provenance, owner, identity, display metadata, and resolved action. |
| `src/app.rs` uses bare IDs and path strings in reuse, dedupe, pins, selection, close protection, and jump-back. `refresh` waits for every collector. | Qualify targets and paths throughout. Apply independent provider updates without blocking the TUI. |
| `src/herdr.rs` runs inherited-route CLI subprocesses without deadlines. | Add bounded structured ordinary-server transport and a separate authorized client route. |
| `src/tui.rs` handles keys only, recreates `ListState`, appends query characters, uses a 48/52 split, and exits an overlay even after action failure. | Store browse/scroll state, edit at a cursor, add real controls, responsive Details, and acknowledged action lifecycle. |
| `src/keymap.rs` and `src/config.rs` reserve source shortcuts, Tab, Ctrl-B/O/U/X, Alt-Enter, and F5 for available updates. | Add focus, expansion, filters, and Refresh without stealing existing bindings. |
| `src/main.rs` supports overlay, side-pane toggle, and jump-back. Side lookup uses label plus the focused workspace. | Separate picker ownership from client selection and bind reused panes only through authenticated invocations. |
| `src/integrations/sessions.rs` lists process-host sessions, strips Herdr environment for local attach, and uses configured `--remote TARGET --handoff` targets. | Keep Attach distinct from live navigation. Do not treat configured remotes as client-discovered machines. |
| `src/integrations/command.rs` already quotes substitutions and bounds collection. Herdr Plus creates tabs/panes before startup commands. | Retain these behaviors, attach provider/action identity, and constrain execution to the provider host. |
| `Cargo.toml` has crossterm 0.29 and ratatui 0.30. `herdr-plugin.toml` declares Herdr 0.7.4 minimum and popup/split entrypoints. | Use existing UI libraries first. Gate new operations by capability rather than assuming the manifest minimum supports them. |

Existing tests are inline `#[cfg(test)]` modules, not a top-level test suite. They cover query operators, all three matchers, source-specific reuse, pins, workspace protection, config aliases, vim keys, TestBackend rendering, session parsing, shell quoting, subprocess limits, and CLI-stub template creation. Preserve those contracts unless this design explicitly replaces them. The agent terminal-target assertion, source-group rendering, color-only marker precedence, pane-derived workspace close, and old launch-mode assertions need replacement tests, not blind preservation.

Herdr 0.9.0 already implements cross-machine navigation internally. The upstream `aggregate_navigation.rs::navigator_rows`, `endpoint_navigation.rs::focus_or_activate`, and native picker/prompt code in `overlay_input.rs` are internal `pub(super)` code. The blocker is plugin access to the invoking client's combined snapshot, exact navigation, and native prompt, not a missing native machine navigator.

## Implementation boundaries

Keep three deep modules with small interfaces rather than adding a generic provider or plugin framework.

- Proposed `src/navigation/mod.rs` owns typed snapshots, capability selection, ordinary-server/client transport adapters, refresh state, and structured focus/native-flow outcomes. App code asks for a snapshot or requests a typed navigation action. Transport details stay private in `navigation/server.rs` and `navigation/client.rs`; subprocess mechanics stay in `herdr.rs`.
- Proposed `src/actions.rs` resolves the displayed action, validates its revision and owner before dispatch, and runs only that action. Preview, footer, keyboard, and mouse read the same action description. Workspace reuse and template rules move here from `App`.
- Proposed `src/picker.rs` owns the browse tree, query/filter projection, expansion, stable row selection, and queued ranking changes. It consumes snapshots and resolved entries without performing I/O. `App` coordinates it with navigation and actions; `tui.rs` renders it.

`model.rs` holds shared identity and row data. Proposed `history.rs` owns versioned pins and client-scoped jump-back. Do not split each row kind into its own service. Add internal files only when they hide a real transport, state, or persistence concern.

## Minimum Herdr capability contract

The following operation names are hypothetical interface descriptions, not available methods, CLI commands, or flags. Agree the wire representation with Herdr before shipping the client adapter.

| Capability | Minimum request/response behavior |
| --- | --- |
| Client route and capabilities | Herdr supplies an invocation-scoped, authorized route to exactly the originating client, including when the plugin runs on a remote server. Negotiate protocol version, combined snapshot, supported exact-focus target kinds, native new-workspace flow, and optional visibility/events independently. Return route expiry and structured unsupported/unauthorized errors. |
| Proposed `navigation.snapshot` | Return the client's Local and saved-machine sidebar order, known selected machine/session and exact current target, connection state, per-machine last successful refresh, per-machine errors, and cached workspace/tab/pane records with agent metadata. Include machine key, session key, server incarnation, object IDs, parent IDs, revisions, useful labels, optional owner paths/home, and tab naming metadata when known. Scope discovery to sessions represented in that sidebar, not every session on every host. |
| Proposed `navigation.focus` | Accept qualified workspace, tab, or pane targets and the invoking-client route. Validate identity, incarnation, availability, and ancestry. Activate that endpoint in that client and focus exactly the requested kind. A workspace request intentionally restores workspace focus; it is not an invented pane request. Return acknowledged previous/current qualified targets or a structured failure. Never create, attach, infer by cwd, or substitute another object. |
| Proposed `navigation.new_workspace_flow` | Accept a qualified machine/session target and an action request ID, not a caller-chosen cwd or name. Activate that machine in the invoking client, then invoke the same native naming flow as `prefix+shift+n` there. Return accepted handoff with a flow ID, or a structured failure. Distinguish prompt opened, cancelled, submitted/created, and failed when completion events are supported. Native defaults and validation belong to Herdr. |
| Optional events and lifecycle | Publish cache changes and picker visibility when available. Define repeated invocation/rebinding, handoff ordering, completion correlation, and route expiry for reused overlays and persistent side panes. Polling a cache is sufficient for discovery; native handoff still needs a reliable acknowledgement. |

The client route grants only these navigation operations. Use Herdr's existing authenticated connection for a remote relay. Do not expose a general client-control socket, trust a correlation ID as a route, choose the first client on a server, or send synthetic shortcut keys. Do not log route secrets or pass them to command integrations. A new invocation may rebind a reused picker only through Herdr-authenticated context delivery.

The snapshot excludes terminal contents and credentials. Navigator does not enumerate SSH profiles, open saved-machine connections, or stream pane output. Connection controls remain Herdr's responsibility unless a separate explicit Connect capability is later approved.

### Capability gates and fallback

| Available support | Navigator behavior |
| --- | --- |
| Ordinary routed server only | Show `Server scope: <known owner>`. Collect all panes and use supported exact server actions. The routed server may be remote. Do not label it Local without client evidence. Show unsupported machine new-workspace actions disabled. |
| Combined snapshot without exact client focus | Do not advertise combined navigation. Keep production navigation server-scoped. Combined fixtures may exercise the UI, but a display-only list is not a shipping cross-machine implementation. |
| Combined snapshot plus exact client focus | Enable combined live navigation for supported target kinds. Keep machine results visible, with native New workspace disabled if that separate capability is missing. |
| Combined snapshot, exact client focus, native flow, valid route | Enable the complete picker, including actionable machine results. |
| Expired route or offline target after collection | Keep the selected row and show the reason. Require a fresh authenticated invocation or explicit refresh as appropriate. Never retry through the process server as a fallback. |

Raw `pane.focus` with `PaneTarget { pane_id }` is the ordinary-server exact-pane mechanism verified in the design notes. Herdr 0.9.0's directional `herdr pane focus` is not that mechanism; `--pane` is the origin. Confirm raw request framing and supported transport against versioned schema/help fixtures before implementation. No exact-destination CLI spelling is assumed here.

## Open upstream questions and blockers

1. What public transport will expose the internal client snapshot, focus, and prompt code? The inspected 0.9.0 plugin interface has no discovered complete contract. U01 must settle wire names and versioning; fixtures must label their schema hypothetical until then.
2. Which machine/session keys survive reconnects, and which server incarnation rejects reused object IDs after restart? Determine what old ordinary-server schemas expose. Without restart-safe evidence, persist no replayable target and do not claim restart safety from a local socket path alone.
3. Can the invocation route bind to the originating client when the plugin process runs remotely? How does a reused overlay/side pane receive authenticated replacement context rather than inherit an old environment? U01/U04 block reuse-enabled combined routing if no safe answer exists.
4. At what point does exact focus acknowledge actual client selection? Does the native-flow acknowledgement occur before or after the plugin overlay disappears? Define ordering so Navigator neither exits on a failed handoff nor covers the naming prompt. U03/U04 block the full action lifecycle.
5. Does Herdr expose native prompt completion/cancellation, idempotent request handling, and the selected machine's default session/name behavior? Define an explicit unknown-outcome path if completion cannot be observed. Never infer creation from an opened prompt or replay a timed-out mutation.
6. Can Herdr report that the original side pane is hidden after client endpoint selection? If not, define a fresh-invocation or explicit suspend fallback that stops refresh and expires stale routes. Do not leave indefinite remote polling as an undocumented behavior.
7. Which public metadata distinguishes manual pane labels, useful titles, and default versus named tabs? Keep unknown tab rows and conservative pane titles until that metadata exists. This question does not block all-pane collection.
8. Can the supported session attach contract express a configured named session plus remote target without changing ownership? Current `remote_entry` ignores configured `session`, while local attach strips Herdr routing variables. Preserve the existing target-only attach behavior visibly until an exact named remote attach is verified; do not display a name the dispatcher cannot honor. This is separate from client live focus and does not justify adding arbitrary remote execution.

These blockers do not justify SSH discovery, public-socket invention, native shortcut injection, or server-local New workspace fallback. N01 through N18 can proceed with offline fixtures.
